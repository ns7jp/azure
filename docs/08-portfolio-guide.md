# 08. ポートフォリオ・面接説明ガイド

## 60秒説明テンプレート

「架空の小規模企業から社内Webサーバー構築を依頼された想定で、要件定義からBicep、試験、運用、障害対応まで作成しました。特に、SSHの接続元制限と鍵認証、HTTPの既定閉鎖、What-If確認、誤削除防止を重視しました。学習コストを抑えるため単一VMとしましたが、可用性が必要な本番では複数AZやロードバランサー、バックアップを追加する判断です。実施済みの静的検証と、未実施のAzure実機試験は分けて記録しています。」

## よくある質問

### なぜVMですか

Linuxサーバーのネットワーク、OS、サービス、監視の基本を一連で示すためです。アプリ運用が目的ならApp Service等のPaaSも比較します。

### なぜ単一VMですか

学習費用を優先した意図的な制約です。可用性要件には不足するため、SLAとRTO/RPOを確認して冗長化します。

### なぜBicepですか

Azureネイティブで、構成差分をレビューでき、再現性と変更履歴を残せるからです。

### 一番危険な点は何ですか

Public IPを持つ点です。SSH元制限と鍵認証で軽減していますが、本番ではBastion、VPN、Private Access、WAF等を要件に応じて検討します。

### 実際に動かしましたか

証跡にある事実だけ答えます。例:「Bicep buildはPASS、Azure実環境へのデプロイは課金を伴うためNOT RUNです」。未実施を曖昧にしないことも運用品質です。
