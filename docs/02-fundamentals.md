# 02. 初心者向け用語と全体像

> [!TIP]
> このページは、設計書を読み進めるための**最小限の11語**に絞った早見表です。「一言では足りない」「たとえや覚え方まで知りたい」段階になったら、[Azure基礎用語集(初心者向け)](11-azure-glossary.md)へ進んでください。分野別に約250語を収録しています。

## まず一言で覚える

| 用語 | 一言 | この案件での役割 |
|---|---|---|
| Subscription | Azure利用の契約・課金単位 | 誤ると別の請求先へ作成される |
| Resource Group | リソースをまとめる箱 | 案件単位で管理・削除する |
| Region | データセンターの地域 | `japaneast` を既定にする |
| VNet | Azure内の専用ネットワーク | `10.20.0.0/16` |
| Subnet | VNetを用途別に分けた区画 | サーバー用 `10.20.1.0/24` |
| NSG | 通信の許可表 | 指定元からのSSHだけ許可 |
| NIC | VMのネットワーク接続口 | Private/Public IPをVMへ接続 |
| Public IP | インターネット側の住所 | 管理・学習確認に使用 |
| VM | 仮想サーバー | UbuntuとNginxを稼働 |
| Log Analytics | ログを集めて検索する場所 | 運用・障害調査の土台 |
| Bicep | Azure構成を宣言するコード | 同じ構成を再現・レビューする |

## 通信の順番

`管理者PC → Public IP → NSGの判定 → NIC → VM → Nginx`

つながらないときは、この順番を逆に調べる。

1. Nginxは起動しているか。
2. VMのOSは起動しているか。
3. NICとIPは正しいか。
4. NSGは接続元を許可しているか。
5. 管理者PC側や経路で遮断されていないか。

## CIDRをやさしく理解する

- `10.20.0.0/16`: `10.20` から始まる大きなネットワーク範囲。
- `10.20.1.0/24`: その中の小さな区画。
- `203.0.113.10/32`: 1個のIPアドレスだけ。
- `0.0.0.0/0`: 全IPv4。SSHの許可元には使用しない。

## IaCの読み方

Bicepは「手順」より「完成形」を書く。

```bicep
resource vnet 'Microsoft.Network/virtualNetworks@2024-05-01' = {
  name: 'vnet-portfolio-dev-jpe-001'
  location: location
}
```

- `resource`: Azureに作る物
- `Microsoft.Network/virtualNetworks`: リソース種別
- `@...`: APIバージョン
- `name`: Azure上の名前
- `location`: 配置リージョン

## 3問チェック

1. NSGとOSファイアウォールの違いは何か。
2. Resource Groupを削除すると何が起きるか。
3. Bicepを使うと、手作業と比べて何をレビューしやすいか。

### 回答例

1. NSGはAzureネットワーク側、OSファイアウォールはVM内で通信を制御する。
2. 中のリソースも削除対象になるため、対象確認が重要。
3. 変更差分、設定の再現性、命名・タグ・セキュリティ設定。
