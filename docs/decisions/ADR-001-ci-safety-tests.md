# ADR-001: CIにBicep警告失敗とNSG安全設定の退行検知を追加する

- 状態: Accepted
- 日付: 2026-09-08
- 要件・課題: [不足点と学習ロードマップ](../09-gap-analysis-and-roadmap.md)は「中: CIのテスト拡充」を挙げ、現状のCIが`az bicep build`中心で設計値や禁止設定の退行を十分検知しないと指摘している。Stage 4の改善候補の一つ「GitHub Actionsへlintと安全設定テストを追加する」に対応する。
- 制約: 実Azure環境への課金・認証情報を使わずに実施できること。既存のCI実行時間を大きく増やさないこと。
- 選択肢:
  - 案A: 何もしない（現状のBicep buildのみを維持）。
  - 案B: `az bicep build`の出力を検査して警告があれば失敗させ、加えてSSH/HTTPの安全設定（`openHttp`既定値、SSHの`adminCidr`限定、`adminCidr=0.0.0.0/0`の拒否）をテキスト検査で検証するステップをCIに追加する。
  - 案C: Bicep用の専用リンター（PSRule for Azure等）を導入する。
- 判断: 案B（`.github/workflows/validate.yml`にBicep警告失敗ステップと安全設定チェックステップを追加）。
- 理由: 追加の外部ツールやAzure認証を必要とせず、既存のazure/cliアクションとpwshステップだけで実装できる。設計判断（HTTP既定閉鎖、SSHの送信元制限）が将来のコード変更で静かに崩れることを、コードレビューだけに頼らず機械的に検知できる。案Cはより網羅的だが、導入・学習コストが高く、今回のポートフォリオ規模には過剰と判断した。
- 影響:
  - 得られる効果: Bicepの構文警告（未使用パラメーター等）とNSG安全設定の退行がPR時点でCI失敗として可視化される。
  - 新たな欠点: 正当な理由で警告が出る変更（未使用のexperimental機能など）は、警告を解消するかCIのステップを見直す追加作業が必要になる。テキスト検査は構造の書き方（`concat`のパターン等）に依存するため、リファクタ時はチェック文字列の更新が必要。
- 検証: `.github/workflows/validate.yml`のCI実行がPR上でPASSすること。安全設定チェックは`openHttp`の既定値を意図的に`true`に変更したローカル検証、またはSSHルールの`sourceAddressPrefix`を`'*'`に変更したローカル検証で、意図通り失敗することを確認する。
- 見直し条件: プロジェクトがPSRule for Azure等の専用リンターを導入する場合、または安全設定のBicep実装を大きく書き換える場合に本ADRを見直す。
