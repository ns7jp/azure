# 12. コスト管理

[用語集トップ](../11-azure-glossary.md) ・ 前: [11. バックアップ・可用性・障害対応](11-backup-dr.md) ・ 次: [13. IaCと開発ツール](13-iac.md)

初心者がAzureで一番怖いのは「知らないうちに課金されていた」です。この不安は、料金を暗記するのではなく、課金の単位を知る・確認する場所を知る・止め方を知る、の3点で消えます。この案件でも、`scripts/deploy.ps1` が既定でWhat-Ifしか実行しないこと、`scripts/remove.ps1` で確実に消せることが安全装置になっています。金額は書きません。単位と確認方法と止め方を覚えてください。

## 12.2 用語解説

### 12.2.1 従量課金(Pay-As-You-Go、都度課金)

- **一言でいうと**: 先にまとめて買うのではなく、使った量に応じて後から請求される料金の仕組みです。
- **たとえると**: 電気やガスと同じです。契約しただけでは増えず、メーターが回った分だけ請求されます。
- **もう少し詳しく**: 初期費用なしで始められ、不要になれば削除して支払いを止められます。反面、自動の上限は付かないため、放置すると増え続けます。クラウドでは作る力と同じくらい**消す力**が評価されます。
- **この案件では**: `scripts/deploy.ps1` は既定でWhat-Ifだけを表示し、`-Apply` を付けない限り作りません。つまり課金を始めません。
- **覚え方**: 「従量」を分解すると「量に従う」。蛇口を開けた時間だけ水道代、が従量課金です。
- **つまずきポイント**: 使っていなければ0円と思いがちですが、起動していなくても存在するだけで課金されるものがあります。
- **関連**: 課金の単位 / 契約形態 / Microsoft Cost Management

### 12.2.2 課金の単位(時間 / GB / トランザクション)

- **一言でいうと**: サービスごとに何を数えて料金にするかが決まっており、その数え方が課金の単位です。
- **たとえると**: 宅配便は箱の大きさ、タクシーは距離と時間、コインロッカーは預けた時間。料金表の見方が違います。
- **もう少し詳しく**: 代表は3種類です。稼働時間で数えるもの(VMなどの計算リソース)、保管容量で数えるもの(ディスクやログの`GB`)、操作回数で数えるもの(ストレージの読み書きなどのトランザクション)。1台のVMでも計算・ディスク・IP・データ転送が別々の単位で同時に走るため、**単位ごとの積み上げ**で考えます。
- **この案件では**: VMは稼働時間、ディスクは容量、Log Analytics Workspaceは取り込んだデータ量が主な軸です。
- **覚え方**: 「時間・容量・回数」の3拍子。時計・体重計・カウンターの3つの道具を思い浮かべます。
- **つまずきポイント**: 料金は1つの単位で決まると思いがちですが、実際は1リソースに複数の単位がぶら下がります。
- **関連**: 従量課金 / 停止していても課金が続くリソース / データ転送課金

### 12.2.3 停止していても課金が続くリソース

- **一言でいうと**: VMを止めても、ディスクやIPのように存在するだけで料金が出るものは残り続けます。
- **たとえると**: 車を車庫に入れればガソリン代は止まりますが、駐車場代と保険料は毎月引き落とされます。
- **もう少し詳しく**: 代表は次の4つです。
  - マネージドディスク: データを保持するため、確保した容量に対して課金が続きます。
  - Public IP: 種類や割り当て状態によっては、使っていない間も課金対象になります。
  - スナップショットやバックアップの復元ポイント: 保存容量に対して課金されます。
  - Log Analyticsに取り込んだデータ: 取り込みと保持に対して課金されます。
  VMの停止も2段階です。OS内のシャットダウンだけでは割り当てが残り計算の課金が続く場合があり、Azure側が**停止(割り当て解除)**になると計算は止まってディスクは続きます。
- **覚え方**: 止めても残るのは「箱と住所」。中身の計算は止まっても、箱(ディスク)と住所(IP)は残ります。
- **つまずきポイント**: シャットダウンしたから無料と思いがちですが、Azure側の状態を確認する必要があります。
- **この案件では**: 学習後は `scripts/remove.ps1` でリソースグループごと削除し、残っていないかを確認します。
- **関連**: 課金の単位 / コスト最適化の基本動作 / Microsoft Cost Management

### 12.2.4 データ転送(下り / Egress)課金

- **一言でいうと**: Azureから外へ出ていく通信量にかかる料金で、入ってくる通信は一般に無料です。
- **たとえると**: 宅配便は受け取りは無料でも、送るときは送料を払います。方向で値段が違う点がそっくりです。
- **もう少し詳しく**: 主な対象は、Azureからインターネットへの送信(下り、Egress)と、リージョンをまたぐ通信です。同じリージョン内やVNet内は扱いが異なります。無料枠が設定されている場合もありますが条件は変わるため、公式の料金情報とCost Managementで確認します。動画や画像の配信、ログの外部転送で急に増えます。
- **覚え方**: 上り(In)は無料、下り(Out)は有料。「出す方にお金がかかる」= 送料と同じ向きです。
- **つまずきポイント**: 通信はすべて無料と思いがちですが、実際は出す方向と地域をまたぐ方向に費用がかかります。
- **関連**: 課金の単位 / リージョンによる価格差 / 見積の前提条件を明記する

### 12.2.5 リージョンによる価格差

- **一言でいうと**: 同じサービス・同じサイズでも、どのリージョンに置くかで単価が変わります。
- **たとえると**: 同じチェーン店でも、都心と地方で家賃が違うため価格が変わるのと同じ構図です。
- **もう少し詳しく**: 単価は地域ごとに公開されます。安いリージョンを選べば単価は下がりますが、利用者からの距離が伸びて遅延が増える、データの所在に関する要件を満たせない、地域をまたぐ通信費が増えるという代償が出ます。**価格・距離・法令**の3点で選ぶのが実務です。
- **この案件では**: 国内利用者向けのため `japaneast`(東日本)を既定にし、安さより距離とデータ所在を優先しています。
- **覚え方**: 「価格・距離・法令」の3点セット。安いから選ぶのではなく、3点をそろえて選びます。
- **つまずきポイント**: 見積のリージョンは適当でよいと思いがちですが、変えると総額が動きます。見積と実装のリージョンはそろえます。
- **関連**: Azure Pricing Calculator / データ転送課金 / 見積の前提条件を明記する

### 12.2.6 無料アカウントと無料枠

- **一言でいうと**: 初めての利用者に配られるクレジットと、条件を満たす範囲なら無料で使えるサービス枠のことです。
- **たとえると**: 開店記念の商品券と、対象商品だけに使える割引クーポン。期限と対象がある点まで同じです。
- **もう少し詳しく**: 恩恵は3段構えです。期限つきのクレジット、一定期間だけ無料になるサービス、期間の制限なく一定量まで無料のサービス。金額・期間・対象は改定されるため、公式の無料アカウントの案内で最新条件を確認します。クレジットを超えた分や対象外のサービスは通常の従量課金になります。
- **覚え方**: 「一時金・期間限定・ずっと無料」の3段構え。順に細くなっていくイメージです。
- **つまずきポイント**: 無料枠なら絶対に請求されないと思いがちですが、サイズや量が枠を外れれば課金され、クレジット切れ後に残したリソースも請求対象です。
- **関連**: 従量課金 / 予算とコストアラート / 契約形態

### 12.2.7 Azure Pricing Calculator(料金計算ツール)

- **一言でいうと**: 作る前に、サービス・リージョン・サイズ・数量を入力して概算費用を出す公式の見積ツールです。
- **たとえると**: 引っ越しの見積です。荷物の量と距離と作業人数を入れて初めて金額が出るところが同じです。
- **もう少し詳しく**: 手順は、サービスを追加する、リージョンとSKUを選ぶ、稼働時間や容量やデータ転送量を入れる、合計を確認する、の順です。見積は保存や書き出しができるため設計書の根拠として残せます。VM単体で終わらせず、ディスク・Public IP・データ転送・監視まで足して初めて実務の見積になります。
- **この案件では**: READMEの安全ルールどおり、実施の直前にPricing CalculatorとCost Managementで確認します。
- **覚え方**: Calculatorは「作る前の電卓」、Cost Managementは「作った後の家計簿」。前と後で対になります。
- **つまずきポイント**: 出た数字を確定金額だと思いがちですが、リージョン・契約・時期で変わる概算です。
- **関連**: TCO Calculator / Microsoft Cost Management / 見積の前提条件を明記する

### 12.2.8 TCO Calculator(Total Cost of Ownership、総保有コスト計算ツール)

- **一言でいうと**: オンプレミスを続ける場合とAzureへ移す場合の総費用を比べるための見積ツールです。
- **たとえると**: 車を買うかカーシェアにするかの比較です。車両価格だけでなく駐車場代・保険・車検まで数年分足します。
- **もう少し詳しく**: TCOは機器の購入額だけでなく、電気、設置場所、ネットワーク、運用の人件費、更新費用まで含めた合計です。オンプレは初期の大きな支出、クラウドは毎月の支出という形の違いがあるため、単月ではなく数年分で比べます。ツールの提供形態や入口は変わることがあるため、Azureの公式サイトで現在の見積ツールを確認してください。
- **覚え方**: 頭文字で覚えます。Total(全部)Cost(費用)Ownership(持つこと)= 持つと全部でいくら。
- **つまずきポイント**: サーバー代だけを比べがちですが、電気・場所・人の時間を入れて初めて比較になります。
- **関連**: Azure Pricing Calculator / 契約形態 / 見積の前提条件を明記する

### 12.2.9 見積の前提条件を明記する

- **一言でいうと**: いつ・どこ・どの構成・どれだけ使う前提で出した金額なのかを、必ず見積の隣に書くことです。
- **たとえると**: 健康診断の数値に「空腹時」か「食後」かの記載がなければ判断できないのと同じです。
- **もう少し詳しく**: そろえる前提は、見積日、リージョン、サービスとSKU、月あたりの稼働時間、ディスク容量、想定データ転送量、割引の適用有無、税の扱い、そして含まれないもの(運用の人件費、ライセンス、外部サービス)です。前提があれば、金額がずれたときに「稼働時間が想定の倍だった」と原因を特定でき、次の見積が正確になります。
- **この案件では**: READMEのコスト配慮に「概算前提の明記」があり、[不足点と学習ロードマップ](../09-gap-analysis-and-roadmap.md)でも見積内訳と実績差異が課題として挙がっています。
- **覚え方**: 「いつ・どこ・なに・どれだけ・除外」の5つを指で折ります。忘れやすい除外を5本目に置きます。
- **つまずきポイント**: 「約」を付ければ概算として十分と思いがちですが、前提のない金額は誰も検証できません。
- **関連**: Azure Pricing Calculator / リージョンによる価格差 / 予算とコストアラート

### 12.2.10 Microsoft Cost Management(コスト管理)

- **一言でいうと**: 実際に発生した費用を、期間別・サービス別・リソース別に見て分析するAzure標準の機能です。
- **たとえると**: 家計簿アプリです。合計だけでなく費目別に並べるから、どこで使いすぎたかに気づけます。
- **もう少し詳しく**: コスト分析では、サブスクリプション、リソースグループ、サービス、タグなどの軸で内訳を見られ、期間の比較や定期的な書き出しもできます。請求の合計額だけでは何が高いか分からないため、**増えた原因のリソースを特定する道具**として使います。予算の作成もこの機能群から行います。
- **この案件では**: 実機で構築した場合は、翌日以降にコスト分析で `rg-portfolio-dev-jpe-001` の内訳を見るのが学習ポイントです。
- **覚え方**: Calculatorは「先読み」、Cost Managementは「後追い」。先読みと後追いをセットで回します。
- **つまずきポイント**: 使った直後に金額が出ると思いがちですが、集計には時間差があるため、その日の表示が0でも安心材料にはなりません。
- **関連**: 予算とコストアラート / タグによるコスト配賦 / 課金の単位

### 12.2.11 予算(Budget)とコストアラート

- **一言でいうと**: 対象範囲と上限額を決めておき、実績や予測がしきい値を超えたら通知を受ける仕組みです。
- **たとえると**: 携帯電話の使いすぎ通知です。通信を強制的に止めるのではなく、超えそうな段階で知らせます。
- **もう少し詳しく**: 対象範囲(サブスクリプションやリソースグループ)、期間、金額、しきい値、通知先を決めて作成します。重要なのは、予算は支出を止める仕組みではなく**通知の仕組み**だという点です。自動で止めたい場合は、通知を受けて処理を動かす仕組みを別に用意します。初心者が最初に作るべき設定はこれです。
- **この案件では**: [不足点と学習ロードマップ](../09-gap-analysis-and-roadmap.md)では「コストの実測と上限管理」が中程度の優先課題で、予算とアラート先の設定が完了の証拠に含まれます。
- **覚え方**: 予算はブレーキではなく**警告灯**。光るだけで、車は止まりません。
- **つまずきポイント**: 予算を作れば自動で課金が止まると思いがちですが、通知だけでリソースは動き続けます。
- **関連**: Microsoft Cost Management / コスト最適化の基本動作 / 従量課金

### 12.2.12 タグによるコスト配賦(Tag、コストアロケーション)

- **一言でいうと**: リソースに付けたキーと値の札を軸に、費用を案件・環境・担当者ごとに切り分けることです。
- **たとえると**: 経費精算で部門コードを書くのと同じです。コードのない領収書は、全社の雑費に埋もれます。
- **もう少し詳しく**: タグはキーと値の組で、Cost Managementの集計軸として使えます。効きどころは運用の統一で、キーの表記が`Project`と`project`のようにぶれると別の軸として集計されます。リソースグループのタグが既定で中のリソースへ自動的に引き継がれるわけではない点、後から付けたタグは過去の実績へ遡らない点も押さえます。
- **この案件では**: Bicepの `commonTags` により、`Project`、`Environment`、`Owner`、`ManagedBy`、`DataClassification` を全リソースへ統一して付けています。
- **覚え方**: タグは**荷札**です。荷札のない荷物は、請求書という倉庫の中で行方不明になります。
- **つまずきポイント**: タグは名前の飾りだと思いがちですが、コスト集計の軸そのもので、付け忘れは後から取り返せません。
- **関連**: Microsoft Cost Management / 命名規則 / リソースグループ

### 12.2.13 予約インスタンス / Savings Plan / Spotの割引

- **一言でいうと**: 長く使う約束をするか中断を受け入れるかと引き換えに、従量課金より安い単価で使える割引です。
- **たとえると**: 鉄道の定期券(期間の約束)、回数券(金額の約束)、当日の空席割引(空きがあれば安い)の3種類です。
- **もう少し詳しく**: 約束する対象が違います。
  - 予約インスタンス(Reserved Instances): 1年または3年、条件を決めて使い続けることを約束します。構成が固まった常時稼働向けです。
  - Savings Plan(節約プラン): 1年または3年、1時間あたりの利用金額を約束します。サイズや配置を変える可能性がある場合に向きます。
  - Spot(スポット): 余った容量を安く使う代わりに、Azure側の都合で中断・退避されることを受け入れます。止まっても再実行できる処理向けです。
- **この案件では**: 短期間だけ動かす学習用の構成のため、長期の約束を伴う割引は前提にしていません。費用を抑える手段は小さいVMと削除手順です。
- **覚え方**: 「期間で約束=予約」「金額で約束=Savings Plan」「中断OK=Spot」。**何を約束するか**で言い分けます。
- **つまずきポイント**: 割引はとにかく得と思いがちですが、使い切れない約束は割高になります。
- **関連**: 契約形態 / Azure Hybrid Benefit / コスト最適化の基本動作

### 12.2.14 Azure Hybrid Benefit(AHB、ライセンス持ち込み)

- **一言でいうと**: 手持ちのWindows ServerやSQL Serverのライセンスを持ち込み、その分の料金を差し引いて使う仕組みです。
- **たとえると**: 道具の持ち込みができるレンタル工房です。場所代だけ払えば、道具のレンタル料はかかりません。
- **もう少し詳しく**: 対象のライセンスと利用権の条件を満たす場合に適用でき、VM料金のうちOSやデータベースのライセンス分を自社の資産で置き換えます。適用条件と対象は契約内容で異なるため、購入前に自社のライセンス状況を確認します。移行案件では、これを見落とすと見積が実態より大きく高く出ます。
- **この案件では**: OSはUbuntu Linuxのため、Windows ServerやSQL Serverのライセンス持ち込みは関係しません。Windows案件の見積で思い出す用語です。
- **覚え方**: Hybrid = オンプレとクラウドの掛け合わせ。「自分の道具を持ち込める店」と覚えます。
- **つまずきポイント**: 誰でも自動的に安くなると思いがちですが、対象ライセンスを保有し条件を満たす場合だけです。
- **関連**: 予約インスタンス / 契約形態 / 見積の前提条件を明記する

### 12.2.15 コスト最適化の基本動作(サイズ見直し・自動停止・削除)

- **一言でいうと**: 費用を下げる基本は、要らないものを消す・使わない時間は止める・過大なサイズを小さくする、の3動作です。
- **たとえると**: 光熱費を下げる手順と同じです。使わない家電を処分し、いない時間は消し、それでも高ければ機種を替えます。
- **もう少し詳しく**: 効果が確実な順に並べます。
  - 削除: 未接続のディスク、使われていないPublic IP、古いスナップショットなど、誰も使わないのに料金が出る置き忘れを消します。
  - 自動停止: 検証環境は夜間や週末に停止する運用にします。計算の課金は止まり、ディスクの課金は残ります。
  - サイズ見直し: 実測のCPUやメモリを見て過大なSKUを下げます。VMサイズの変更は再起動を伴います。
  Azure Advisorのコスト推奨を入口にすると、勘ではなく数字で判断できます。
- **この案件では**: 学習後は `scripts/remove.ps1` にリソースグループ名を二重指定して削除します。二重指定は消す対象を打ち間違えないための安全装置で、削除後の残存確認までで1セットです。
- **覚え方**: 「消す・止める・小さくする」の3動作。効果が強い順、かつ作業が簡単な順に並んでいます。
- **つまずきポイント**: 最適化はSKU変更から始めがちですが、置き忘れリソースの削除が最も速く確実に効きます。
- **関連**: 停止していても課金が続くリソース / Microsoft Cost Management / 予算とコストアラート

### 12.2.16 契約形態(従量課金 / CSP / EA)

- **一言でいうと**: 誰と契約して誰から請求を受けるかの違いで、同じ構成でも支払い方法や支援体制が変わります。
- **たとえると**: 同じ電気を、事業者から直接買うか、代理店経由で買うか、会社の一括契約で使うかの違いです。
- **もう少し詳しく**: 実務でよく出会うのは次の3つです。
  - 従量課金の直接契約: Microsoftと直接契約し、クレジットカードなどで支払います。個人や小規模、学習用に向きます。
  - CSP(Cloud Solution Provider): パートナー経由で契約し、請求もパートナーから受けます。日本語の一次サポートや請求書払いを受けやすい形です。
  - EA(Enterprise Agreement): 企業とMicrosoftの包括契約で、大規模利用向けです。部門単位の割り当てや管理を行います。
  契約の名称や体系は改定されるため、最新の区分は公式情報で確認します。
- **この案件では**: 学習は個人の従量課金サブスクリプションを想定します。READMEの安全ルールどおり `az account show` で対象を確認し、学習用以外では管理者の承認を得ます。
- **覚え方**: 「自分で買う=従量課金」「代理店から買う=CSP」「会社が一括で買う=EA」。買い方の3段階です。
- **つまずきポイント**: 料金表の数字は誰でも同じと思いがちですが、契約形態と割引で請求額が変わります。
- **関連**: 従量課金 / 予約インスタンス / Microsoft Cost Management

## 12.3 このセクションの覚え方まとめ

コスト管理は、時間軸に沿って3つの局面へ並べると迷いません。

```text
作る前  : Pricing Calculator / TCO Calculator で概算 → 前提条件を書き残す
作るとき: タグを付ける → 予算とコストアラートを置く → What-Ifを見てから -Apply
作った後: Cost Managementで内訳を見る → 消す・止める・小さくする → 最後に削除
```

- 3つの局面の合言葉は「**見積・見張り・見直し**」。Calculatorで見積り、予算で見張り、Cost Managementで見直します。
- 課金の単位は「時間・容量・回数」の3拍子。1リソースに複数の単位がぶら下がることを忘れないでください。
- 止めても残るのは「箱と住所」= ディスクとIP。安心して眠るには、止めるだけでなく削除まで行います。
