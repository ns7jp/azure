# 17. 理解度チェック

[用語集トップ](../11-azure-glossary.md) ・ 前: [15. 混同しやすい用語の対比](15-confusions.md) ・ 次: [18. 索引](18-index.md)

用語集を読み終えたあとに残るのは「読んだ気がする」という感覚だけになりがちです。この節は、その感覚を**説明できるかどうか**という客観的な結果に置き換えるための自己採点用の問題集です。全66問を4つのレベルに分け、レベルが上がるほど「言葉を知っている」から「案件を語れる」へ近づく作りにしています。解答は17.6にまとめてあるので、先に問題だけを解いてから答え合わせをしてください。

## 17.1 使い方と採点の基準

解くときのルールは3つだけです。

1. **紙かエディタに書く前に、まず声に出して答える。** 面接と現場で必要なのは書く力ではなく、その場で話せる力です。
2. **1問30秒で切る。** 30秒で出てこない用語は「覚えていない」と判定します。悩み続けると、覚えていないことを覚えていると誤解します。
3. **答え合わせは○か×の2択にしない。** 次の3段階で採点します。

| 判定 | 基準 | 次にやること |
|---|---|---|
| ○ | 解答の要点をほぼ言えた。たとえ話も添えられた | 触らない。復習の対象から外す |
| △ | 意味は分かるが言葉が出てこない、要点を1つ落とした | 該当用語の「一言でいうと」と「覚え方」だけ読み直す |
| × | 答えられない、または別の用語と取り違えた | 該当用語の本文を通読し、翌日もう一度この問題を解く |

△と×だけを別紙に書き出し、**翌日・3日後・1週間後**に解き直してください。全問を繰り返すより、落とした問題だけを3回回すほうが定着します。

| レベル | 問題 | 何を測るか | 目標 |
|---|---|---|---|
| レベル1 | Q1からQ36 | 分野ごとの基本用語を一言で言えるか | 30問以上 |
| レベル2 | Q37からQ48 | 似た2語の違いを30秒で言えるか | 9問以上 |
| レベル3 | Q49からQ56 | この案件の構成を自分の言葉で語れるか | 全問 |
| レベル4 | Q57からQ66 | 数字と既定値を正確に言えるか | 8問以上 |

レベル3は**面接で必ず聞かれる範囲**です。ここだけは満点を目標にしてください。

4つの目標をすべて満たすと合計55問です。まず55問を到達点にし、17.7の「60問以上」は用語集を一周したあとの仕上げの目安として使ってください。

## 17.8 仕上げ: 3分で構成を説明する台本

面接や社内レビューで最初に求められるのは、用語の定義ではなく**構成の説明**です。次の5つの箱を順に埋めれば、3分で話せます。合言葉の「5つの決」(要件を決める / 構成を決める / 設定を決める / 確認を決める / 運用を決める)と同じ順番です。

```text
1. 要件  従業員50名のSample Works社、小規模な社内向けLinux Webサーバー1台
2. 構成  RG / VNet 10.20.0.0/16 / Subnet 10.20.1.0/24 / NSG / Public IP / NIC / VM(Ubuntu + Nginx)
3. 設定  SSHは公開鍵のみ、接続元はadminCidrだけ、HTTPはopenHttp=falseで既定は閉、監視はCPUアラート
4. 確認  deploy.ps1はWhat-Ifが既定、verify.ps1で作成後の確認、実環境の構築はNOT RUN
5. 運用  未実装はAMA/DCR・通知・バックアップ・HTTPS・冗長化。発展課題として整理済み
```

この台本の強さは、**できていないことを言える**点にあります。未実装を「発展課題」として順番付きで語れると、知識ではなく設計の判断力を示せます。詰まったら[ポートフォリオの見せ方](../08-portfolio-guide.md)と[ギャップ分析とロードマップ](../09-gap-analysis-and-roadmap.md)を合わせて読んでください。
